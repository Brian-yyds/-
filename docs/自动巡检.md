# 自动巡检与保守修复

随原桌面启动器一起运行，无需修改快捷方式。首次启动等待5分钟让采集建立心跳，以后正常每小时巡检一次；进程意外退出在启动器两秒循环中发现。关闭网页不影响巡检，电脑和启动器进程需要保持运行。

检查本启动器管理的币安采集、GMGN、Web3及特级汇总、律动、打包进程和本机页面。只读本地心跳、链成功时间、特级快照时间、进程身份及本地网页健康接口，不调用外部行情接口，不额外消耗GMGN或律动额度。没有新警报不等于故障。

存活进程超过心跳容忍期，需间隔至少30秒的两次检查都异常才重启。新进程有5分钟启动宽限，币安市场扫描额外容忍15分钟初始化；GMGN检查考虑自定义扫描周期。重启后5分钟复查，再恢复正常小时巡检。每个服务每小时最多3次重启，失败按至少60秒、300秒间隔退避，不拖停其他健康采集。

仅操作本启动器记录的子进程，校验PID、创建时间及准确脚本路径，避免PID复用误杀。停止监控时不自动拉起，禁用的来源不恢复。只重启程序，不重写源码、清库、清警报、重置每日去重、改阈值、改密钥或恢复暂停的SFTP。接口已进入退避/限流时保持等待；有心跳而远端数据失败时记录来源延迟，不用重启刷接口。网络中断、服务商故障、额度耗尽和数据库损坏不能承诺自动修好，也不绕过限制。

结果在“设置与调试→诊断”的自动巡检状态，以及本地user_data/health-audit.jsonl。日志达到1MiB滚动保留一份，只有受控状态码、服务名和动作，不包含Key、接口响应或配置明文。

手动检查：使用运行网站的同一Python环境执行 `python health_check.py`；请求安全修复：`python health_check.py --repair`。脚本不自行找端口杀进程，仅向仍在运行且身份核验通过的启动器请求复查，启动器仍执行两次确认、限次及暂停保护。启动器本身被关闭、电脑关机或休眠期间不会运行巡检，脚本也不擅自重新开启整个监控。

隔离测试覆盖阈值/心跳/初始化、暂停与限流、网页无响应、来源延迟、特级快照停滞、数据库损坏不改库、进程身份、30秒确认和修复限次；另外用临时无网络工作进程真实退出验证单进程恢复，不碰实际行情进程。
