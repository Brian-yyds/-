# Perp Radar · 币安永续异动监控

当前版本是**低噪音监控工作台**：1小时OI/上涨/下跌排行榜、蓄势候选、订单流与流动性确认事件，以及可随时调阈值的15分钟急涨/急跌独立报警。打开：http://127.0.0.1:8501 。

**全市场版**：自动扫描所有正在交易的USDT加密资产永续，默认排除BTC与指数；本次实时识别522币。涨跌榜、OI榜和独立报警不受自选池50币限制。深度池最多50币，只用于高频OI、主动成交流、盘口与AI。币种范围随交易所更新，排除项可修改。

## 先这样用

1. 首页自动扫描全市场，无需先选择币；首次补齐全部历史数据约需数分钟，显示覆盖进度，缺数据不填0。
2. 把最关心的币标为“★重点”，首页可切换“仅重点”。
3. 设置上涨/下跌、OI增/减仓、成交额放大的阈值，以及最低窗口成交额。
4. 按需要给单个币设置不同阈值；单币规则优先于默认规则。
5. 默认开启低噪音模式：单项命中只在榜单标记；组合条件持续30秒才写入确认事件，候选只在首页安静展示。
6. “订单流与分析”查看主动买卖、盘口价差、深度和模拟滑点，以及本机证据解读。
7. 如需外部AI，到“AI接口设置”保存自己的配置，再手动调用；也可选择仅新确认事件自动复核。

“全市场基础异动线索”筛选价格、放量、实时OI中至少两项达标的币，可一键加入重点与深度池。盘口/订单流组合确认属于深度池，不能将缺少逐笔或盘口数据的币声称为已完成深度确认。

## 监控分层

- **蓄势候选**：1小时价格仍在安静区间，同时放量、实时OI增加、5分钟主动买入占优且价差达标。只观察，不刷事件；不能保证提前预测启动。
- **上行异动确认**：1小时上涨达标、放量、主动买入占优，同时价格带盘口覆盖完整且价差达标。
- **抛压异动确认**：1小时跌幅或5分钟加速下跌达标、主动卖出占优、放量或大额聚合卖出，且买盘下降/失衡/卖出滑点提供支持。
- **独立急涨急跌**：保留15分钟窗口，默认涨/跌各10%，可分别修改。绕过普通组合、成交额与重点过滤，触发后置顶至确认。

常规确认默认要求1小时成交额≥100万USDT，持续满足30秒、解除60秒后重新武装，并遵守同币冷却；同一波持续命中不定时刷事件。可只对重点币种记录常规确认。参数在“重点币种与规则”调整，属于可调初始规则，未经胜率验证。

## 订单流与流动性

- 1小时主动成交差来自分钟K线的真实USDT成交额及taker buy quote；5分钟主动成交差来自实时aggTrade，买方为maker时记主动卖出。
- 5分钟数据只作短线确认，不改变1小时主排行窗口。断线或聚合成交ID缺口后重新积累连续5分钟；不足、过期不确认。
- 主动成交差=主动买成交额−主动卖成交额，不是资金净流入；单条聚合成交不代表单个大户订单。
- 盘口采用500档公共REST快照，约30秒采样；显示价差、指定价格带的买卖深度、覆盖情况和指定金额模拟买卖的VWAP/滑点。
- 500档未覆盖整个价格带时，深度只是下界，不计算其失衡或深度下降信号；模拟金额超出500档时不伪造完整滑点。
- 买盘深度下降比较此前1–5分钟同一价格带、价格相近且覆盖完整的新鲜快照的中位数，至少4个且跨越90秒。快照变化不能证明撤单；未覆盖隐藏流动性，不是完整L2撤单追踪。

## AI分析

支持多个OpenAI兼容Chat Completions配置（可接支持此协议的服务或本机模型）、Anthropic Messages、Gemini Generate Content配置；模型ID、基础地址、输出上限均可填。兼容接口可选max_tokens或max_completion_tokens。

默认手动调用。自动复核仅针对新确认的上行/抛压事件；蓄势候选不自动调用。提供同币间隔、全局每日次数上限，失败不自动重试，过期排队快照跳过。后台分析不会阻塞行情采集。

AI输入是带时间、来源、覆盖情况、规则版本的证据快照。输出需区分确定事实、可能解释、反证、后续确认/失效条件和缺失项。OI增仓不等于多头；AI结果不触发下单。

本机证据解读明确标识为规则分析，不冒充外部模型。可下载证据包带回当前对话，让助手分析；网站不能把当前聊天自动变成常驻模型。外部AI需要你自己的API配置及额度，真实调用前需自行填写密钥。

Windows密钥通过当前系统账号的DPAPI加密，保存在user_data/api_keys.dpapi.json，不进入证据包、日志或源码压缩包；也可使用环境变量。变更地址/协议需重新填密钥，任务执行中不能改配置。仅向用户配置的接口发送公开市场指标，不包含账户、订单或交易所密钥。迁移密钥到另一台电脑需要重新输入。

## 更新与口径

- **价格**：全市场ticker与每个合约的1m线实时推送，REST每30秒核对。约2秒写一次快照，页面每3秒刷新。
- **OI**：全市场分批公共接口轮询，约60–180秒，重点/深度池约10秒。扫描器限制为每秒最多12个请求、14点请求权重，和深度池分开运行。实际间隔受网络、币数和交易所退避影响，状态页显示真实进度。按持仓数量计算变化，USDT规模用最新价近似折算。
- **1小时涨跌**：修正了旧版误用59分钟前开盘价的问题。启动时取最新价格时间往前1小时所在分钟的开盘价，实际跨度60–61分钟；参考时间、参考价和跨度逐币展示。积累满1小时实时价格后，优先取目标时刻前10秒内的样本，不使用目标之后的数据，不插值。实时样本按5秒桶保留首个观测。
- **24小时对照**：并列显示币安官方ticker的priceChangePercent，直接取交易所数据；1h主榜不会把24h字段冒充1小时幅度。比如一个币过去24小时上涨，最近1小时仍可能急跌。
- **窗口成交额**：最近60根1m线，包含未收盘分钟，约59–60分钟；与价格参考跨度区别已说明。
- **成交额**：直接累计K线的USDT成交额字段，不用基础币成交量冒充成交额，也不以24小时滚动成交额差计算短周期成交额。
- **成交额放大倍数**：最近N根已收盘1m成交额，除以前N根已收盘1m成交额。避免把半根分钟和整根分钟作同比。
- **OI启动基准**：先取5m历史快照并显示实际跨度，历史基准只排行、不用于确认OI增仓。积累满窗口后切换到实时基准；全市场目标前最多180秒，深度池最多45秒，实际跨度均展示。
- **数据过期**：全市场排行价格最长90秒、OI最长180秒；深度分析仍使用价格20秒、OI40秒的严格门槛。当前分钟数据超过25秒时，不给出有效窗口成交额。缺失/过期不伪造0。
- **断线恢复**：自动重连和REST补齐；全市场冷启动补齐125根分钟线，随后流式更新并周期复核。重启复用数据库中完整历史，避免重新逐币全量下载。

## 规则与排行

### 15分钟独立报警（默认 ±10%，可随时调）

全市场范围内所有币种均启用，不限深度池。最新价格相对过去15分钟内先前低价上涨或先前高价下跌达到独立阈值时报警；无需等待15分钟K线收盘。涨跌阈值分别设置，保存后约3秒内对下一笔有效行情生效。历史记录保留触发时阈值。实时价格流驱动全市场检查，深度币另有K线驱动，断线时退回REST轮询。

它独立于1小时规则，不受最低成交额、OI条件、单币常规告警开关或常规冷却时间限制。涨跌分方向记录；同一波持续超阈值只挂一次，回落至当前阈值的95%以下后重新武装。确认报警不会让持续中的同一波行情立即重复报警，反向急变仍可独立记录。降低阈值会对当前新行情重新检查，不追溯重写旧报警。

报警以红色区域一直挂在首页，直到点击“确认以上独立报警”；不受“仅重点”、币种搜索等排行筛选影响。确认后保留在独立报警历史中。重启也会保留待确认报警及去重状态。

启动/重连时，以窗口内完整已收盘1m K线的高低点补充先前参考价格，其极值具体发生时刻未知，因此报警间隔显示上界“≤”；持续运行后同时使用实时价格采样。窗口左边界不足整根分钟的部分不使用历史高低点猜测。报警反映接收到的行情，不保证捕获推送间隙里的每一笔成交。

### 1小时常规规则

- 任一条件：上涨、下跌、OI增仓、OI减仓、成交额放大中任何一项达到阈值。
- OI且价格：OI增/减仓与价格涨/跌同时达到各自阈值。
- 最低窗口成交额是所有触发条件的前置过滤。
- 默认低噪音模式：单项命中只标记，组合确认才记录；关闭低噪音后，恢复原单项规则按冷却重复记录的方式。
- 排行默认展示全市场山寨币，提供前三十名和全市场明细，可搜索、切换仅重点、只看命中。OI可切换增/减仓；涨跌方向分榜。
- 重点标记用于突出和深度订阅，不会限制其他币的全市场排行或独立报警。单项命中在全市场标记，深度池组合确认/原单项事件使用深度池的高频数据。

## 启动与停止

当前会话已启动；后续运行 `start.ps1`，停止运行 `stop.ps1`。

迁移到其他Windows电脑时，安装Python 3.11+（建议3.12），先运行 `setup.ps1` 安装监控版依赖，再运行 `start.ps1`。网络需能够合法访问币安公共接口与行情流。不需要API Key、Docker或交易账户。

关闭浏览器后继续采集；电脑需保持运行和联网。当前不是开机自启服务，也未配置外部消息推送。异动只保存在本机SQLite并显示在工作台。

## 数据与文件

- `app.py`：监控界面；`live_collector.py`：全市场价格/K线流、深度采样、规则；`market_scanner.py`：全市场历史/OI采集及请求节流。
- `monitoring.py`：规则与榜单计算；`radar.py`：订单流、盘口与降噪；`ai_analysis.py`：AI适配、队列和密钥；`store.py`：本机SQLite。
- OI采样保留48小时，分钟K线保留3小时，异动事件保留最近5000条。
- `user_data/workbench.sqlite` 包含监控池、重点、单币规则与历史记录；迁移时先停止服务，再复制数据库。
- `requirements.txt` 为监控版依赖，`requirements.lock.txt` 为已验证环境快照。
- 原研究代码与历史回测文件保留在目录中，默认不启动、不出现在当前主界面；如有需要可另行使用 `requirements.research.txt` 安装研究依赖。
