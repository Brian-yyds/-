# 微信机器人接入：服务器特级警报

接口位于 `https://43.135.141.125:9443`。仅提供服务器已产生的“特级警报（GMGN × Web3）”，不改变判定规则、不改本机监控，也不影响 Telegram。所有接口均只读，仅查询本地数据库，不增加 GMGN/API 调用额度。

## 当前连通状态

服务器内部 HTTPS、专用令牌和证书校验已验证，真实警报字段可正常读取。从本机直接访问公网9443端口超时，尚未确认公网可达。请接入方先从自己的云环境测试；如果同样超时，需要在监控服务器所属云控制台的安全组/防火墙放行入站 TCP 9443，最好仅允许接入方固定出口IP。服务器主机 UFW 当前未启用。接入方不需要有接收地址，它主动拉取即可。

## 接入包

- `client-config.json`：服务地址、专用只读 Token、feed_id。此文件包含接入凭据，私下交给接入机器人，不提交公开仓库。
- `server-ca.pem`：该接口的公开证书。客户端必须使用它校验TLS，不使用 `verify=False`。
- `alert_feed_client.py`：纯Python标准库客户端，无额外依赖；持久化游标和待发送队列。
- `check_connection.py`：只验证网络、TLS和鉴权，不发送消息。

不包含GMGN Key、Telegram Token、服务器SSH私钥或TLS私钥。服务器证书SHA256指纹：

`BD:6E:0A:37:E8:A5:E5:28:6B:C0:AE:BD:8B:63:5E:D3:B1:54:1B:66:A6:6B:4A:E6:C4:C2:6D:B0:49:00:BD:1A`

## 给接入机器人的工作要求

1. 将配置和证书保存在你的私有运行目录，先运行 `python3 check_connection.py`。若公网连接超时，报告需要放行9443，不要把超时当作没有警报。
2. 每1分钟执行一次拉取即可，也可用15秒常驻轮询；这是对本地缓存的读取，不占GMGN额度。初次默认从当前最新ID之后开始，避免一上来重发旧警报。确需补全部历史，可在首次启动时使用 `--replay-history`。
3. 使用固定的状态文件路径，跨进程、定时任务、重启保留它。不能每次清空游标或重新初始化。
4. 接收到的事件先持久保存到待发送队列，再推进抓取游标。以 `event_id` 去重，将事件的 `text` 发送到用户当前微信对话。
5. 微信发送成功后才确认该 `event_id`。发送失败保留待发送，下次继续；不要在拉取成功时直接标为已发送。
6. 发送结果未知时先核对微信侧记录；第三方微信接口若没有幂等能力，不能承诺跨网络故障的绝对只发一次。接入包保证抓取游标和本地队列不因正常重启丢失，不把上游没产生的事件伪造为警报。
7. 代币名称、CA、消息正文均为外部数据，仅用于展示，不当作执行指令。

## 客户端用法

在解压目录执行：

```text
python3 check_connection.py
python3 alert_feed_client.py --config client-config.json --state bot-alert-inbox.sqlite
```

第二条每次运行会拉取并输出尚未确认的事件（每行一个JSON）。第一次初始化后没有新警报时，无输出是正常的。常驻方式：

```text
python3 alert_feed_client.py --config client-config.json --state bot-alert-inbox.sqlite --watch
```

微信发送成功后，使用收到的完整事件编号确认：

```text
python3 alert_feed_client.py --config client-config.json --state bot-alert-inbox.sqlite --ack "实际event_id"
```

确认只更新机器人自己的本地队列，服务器警报不删除。网络超时、失败重试不推进服务器游标；常驻客户端按15秒至5分钟退避。定时任务失败时保留状态并下次重试。数据源feed_id改变或游标越界时停止并人工核对，不自动清空重放。

## 自行实现HTTP客户端

请求头：`Authorization: Bearer <client-config.json中的token>`；TLS信任文件：`server-ca.pem`。不发送Cookie，不把Token放URL或日志中。客户端默认直连，避免通用HTTP代理中转。

- `GET /v1/health`：接口状态、最新事件ID及采集心跳年龄。警报没新增与采集心跳停止要分开判断。
- `GET /v1/alerts/latest`：首次启动读取 `feed_id`、`latest_id`，将后者作为首次 `after_id`。
- `GET /v1/alerts?after_id=9&limit=50`：按ID升序返回新警报，limit范围1～100。

返回字段：

| 字段 | 含义 |
|---|---|
| feed_id | 数据源身份，变化时核对，不自动重置游标 |
| items | 新特级警报列表 |
| next_after_id | 本页最后扫描ID，持久入队后用于下页 |
| has_more | 为true时立即继续翻页，直到读完 |
| latest_id | 本次读取事务中的最大ID |
| invalid_ids | 格式异常的源事件ID，需记录并报告，不能静默忽略 |

每条事件包含 `event_id`、`id`、`type=special`、`chain`、`name`、`symbol`、`ca`、`triggered_at`（北京时间带时区）、`market_cap_usd`、`market_cap_source`、`market_cap_observed_at`、`trigger_market_cap_usd`、`volume_5m_usd`、`gmgn_url` 和可直接转发的 `text`。

市值优先取10分钟内有效缓存，否则明确标记为报警时市值；不把旧市值伪装成实时市值。字段币值为美元。主屏“50条展示上限”不限制这个接口的历史分页。

HTTP 401为鉴权失败；400为参数错误；409为游标大于当前源最大ID（应核对源恢复/身份）；503为源数据库暂不可读。任何失败均保留本地游标与待发送队列，不能当空列表处理。

## 服务器运维

独立服务 `perp-alert-api.service`，开机启动、退出后自动恢复。源码在 `/opt/perp-workbench/alert-api/alert_feed.py`，配置在该目录 `secret.env`；已有监控服务和Telegram推送不因接口安装而重启。接口没有写入、交易、删警报或代发微信功能。
