# 采集器 → SFTP 接收服务器

网站继续运行原有监控，另由 `export_worker.py` 独立整理和发送数据。关闭浏览器不影响后台；电脑仍需开机联网。SFTP 故障不会阻塞币安或 GMGN 的采集，也不会触发交易。桌面快捷启动器不变，新同步后台随 `launch.py start` 一起启动。

## 首次设置

1. 更新依赖 `python -m pip install -r requirements.txt` 并重新启动工作台。
2. 打开 `/settings` → **采集与同步**，填写接收服务器、22端口、用户名及服务器 SFTP 视角的绝对目录（例如 `/inbox`）。默认发送间隔60秒，可调整为其他30–86400秒。
3. 生成专用 ed25519 密钥。把页面上的公钥完整一行加入接收端用户的 `~/.ssh/authorized_keys`。可将该公钥限制为 `restrict`，只供此采集器使用。接收端配置用户及目录写权限，保留 SFTP 子系统。
4. 点击“读取服务器指纹”。由服务器控制台运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`，核对页面显示的 SHA256 指纹，然后填入并保存。探测连接不进行认证或发送数据；只有人工核实后才固定信任。
5. 测试密钥登录与目录，启用定时上传。首次写权限由实际上传验证。首次可能有多包历史警报等待发送；后续每个时间间隔产生一个快照包。

Windows：私钥在 `user_data/sync/id_ed25519.dpapi`，采用当前 Windows 账户 DPAPI 加密；公钥为同目录 `id_ed25519.pub`。不使用密码、不读取 SSH Agent、不读取其他 SSH 身份或钱包配置。Linux：私钥位于 `user_data/sync/id_ed25519`，权限0600。迁移机器时应生成新身份并重新安装公钥；不要把 Windows 加密私钥当作跨机器通用密钥。

服务器地址、用户名、间隔及已核验主机公钥保存在本机数据库 `sync_config`，不写入公开源码。SSH私钥、GMGN密钥、AI配置、本地连接配置均不导出或提交 Git。

## 接收文件

每个正式文件命名：

```
monitor-{collector_id}-{sequence:09d}-{UTC日期时间}-{packet_id}.json
```

编码为 UTF-8，未压缩的标准 JSON，单包最多20MB。上传顺序为：

```
/inbox/.monitor-….json.tmp   # 传输过程中，接收端忽略
/inbox/monitor-….json       # 上传结束并确认大小后，在同目录改名
```

接收端只扫描 `monitor-*.json`，忽略以点开头或以 `.tmp` 结尾的文件。完整包在同目录改名后才可见，避免读取半个包。同名正式文件已存在时先检查长度和SHA256；内容相同即视为已交付，不再写入，不覆盖不一致的文件。若接收端在处理后移动/删除文件，应在自己的消费数据库中保留 `(collector_id, packet_id)` 去重记录，处理提交成功后再归档。SFTP交付成功不等于下游分析已消费成功；此协议不包含业务消费回执。

请在服务器侧安排归档及磁盘保留策略。发送端不会删除服务器上的正式文件。若采用受限 SFTP/chroot，`/inbox` 指的是该用户登录后的文件系统视角，无需开放 shell 登录。

## JSON 合同 1.0

顶层：

| 字段 | 说明 |
| --- | --- |
| `schema` / `schema_version` | 固定 `perp-workbench.monitor` / `1.0` |
| `collector_id` | 本机持久身份，重启不变；不要让两个采集器共用并同时写一个 outbox |
| `packet_id` | 此包UUID；重试保持原ID和原内容 |
| `sequence` | 本采集器已入队包的递增序号 |
| `generated_at` | Unix秒；仅是打包时间，不代替行情采样时间 |
| `timezone` | `Asia/Shanghai`；K线/事件的原有毫秒字段保持毫秒 |
| `modules` | `{模块名: {version,status,data}}`，未知模块可忽略；模块失败为 `unavailable`，其他模块继续 |
| `events` | 新警报及近期状态；见下文 |
| `event_cursor` | 本包读取前后警报ID、是否还有历史页 |
| `coverage` | 本包数据边界，明确没有包含原始数据库或全部历史K线 |

现有模块：

- `binance_market`：当前有效合约分类清单、全市场最新价/24h参考数据、滚动4h价格与OI指标及基准、四类排名符号列表、重点币种报价和当前15m警报阈值。排名不套用网页临时搜索/显示筛选。股票、ETF和大宗正常纳入主监控；BTC虽默认不进排名，仍保留行情和重点数据。`price_change` 是4h；`change24h` 是币安24h参考，两者不得混淆。`event_time/price_time/oi_time/base_time` 等毫秒字段与原监控一致；`price_fresh` 和来源时间用于判断可用性，不能把旧数据当实时数据。
- `gmgn`（模块version=2）：四链报警规则及`watch_ranking`。仅真实报警后固定10日内的代币，按真实近1小时美元成交额前10。排名含首次报警、固定到期、最近报警、成交额及观测时间，`total/fresh/complete`表明覆盖；删除旧`hot/hot_leaders/hot_updated/volume_leader`。每日最多1次，时区Asia/Shanghai，复报不续期。当前今日毕业阈值150K、非发射台1M，两类KOL大于1；`smart_money_required=false`表示聪明钱不作门槛，旧`people`已移除。`alarm_time_timezone=Asia/Shanghai`，事件`triggered`为原始触发的Unix秒，接收端转换为北京时间显示，不用`last_seen`替代报警时间；详见 [GMGN十日跟踪](GMGN十日跟踪.md)。
- `market_volume`（模块version=1）：30个北京时间自然日的全加密市场及每日前10成交额，`window_days=30`，`days`保留每日`quote`、`top10_quote`和前10合约明细，使用USDT计价；今天未结束。继续仅在此统计排除币股、大宗及ETF。字段兼容原格式，接收端按`window_days`及`days`长度显示，不固定取15条。暂停上传时仍在本机更新30日数据包；只有明确恢复上传后才继续发送。
- `blockbeats_news`（version=1）：律动中文快讯缓存最新100条，`poll_seconds=300`，包括`id/title/content/link/published_at/published_text/observed`。正文为去除HTML后的纯文本，`published_text`保留来源原始发布时间；无时区字符串按北京时间解析。不是逐条消费事件，不重复当作新报警；接收端按快讯ID去重。含`observed_at/next_poll_at/coverage_limited`，不含Key。暂停SFTP时仅本机更新，不会自行恢复外发。
- `health`：各采集源心跳、连接状态、限流等待等公开字段。异常原始文本不导出，避免带出本地地址、请求头或密钥。

`events.spike_alerts`、`events.gmgn_alerts` 各含：

- `new`：按ID正序，每包各最多1000条未曾入队的新记录；初次从数据库目前仍保留的记录开始，历史很多时会在后续包继续分页。入队与推进游标在同一个持久事务中完成。
- `recent`：最新100条记录的当前状态，包括确认状态；GMGN的 `last_seen` 和数据可能更新。接收端按 `(collector_id, 事件表名, id)` upsert，不要把 `recent` 当成新增警报重复推送。
- `has_more`：仍有历史页待导出。只能保证本机仍保留的数据，历史清理或超长离线后的已删除记录不能恢复。`recent`之外的老记录确认更新不保证回传。
- GMGN警报继续排除币股/ETF，`rules.exclude_equities=true`；有效`new/recent`同时过滤旧同币同日重复。`suppressed`给出本包读取范围内的旧记录ID、链、地址和原因：`tokenized_equity`或`duplicate_beijing_day`，接收端据此停用原ID，不当作新报警。游标始终按原始记录推进；不能因过滤项而停住。

每包是当前状态快照加警报增量。不会发送私钥、账户/API Key、AI配置、进程信息、本地完整SQLite、逐笔成交、完整历史K线或盘口数据库。它适合远端重建监控、告警和后续分析输入，不应把每分钟一次快照称为逐笔行情存档或用来替代完整回测数据源。

## 失败与暂停

- 发送失败按10、20、40、80、160、320、600秒退避，之后最多每600秒重试；每次写本机轮换日志 `user_data/sync.log`，连续失败次数和下一次重试时间可在设置页查看。成功后清零失败计数。
- 待传包及游标在 `user_data/sync/outbox.sqlite`，按先入先出发送，重启恢复。最多720个待传包或256MB，触顶时保留已有包、暂停新包入队，不默默删除警报游标。`latest.json`仍更新；长期满队列导致本机历史清理的记录可能无法补回。
- 默认未启用外传时仍每60秒更新本机 `user_data/sync/latest.json`，可在设置页下载；不推进已交付/已入队警报游标，也不产生外网请求。
- 地址、用户名、目录或固定服务器公钥改变后，旧队列保留并暂停发送，防止旧数据自动流向另一目标。恢复原目标可继续。更换服务器需明确处理原队列及重新核验身份，程序不替用户丢弃或重定向待传包。
- 网站关闭浏览器继续采集；机器睡眠、关机或断网时无法按时发送，恢复后继续。本地和远端时钟应正常同步。

## 后续加监控功能

已有规则、阈值、重点币种调整，会在下一包自动读取，无需修改接收服务器或桌面快捷方式。新增模块在 `data_export.py` 通过 `@section('module_name', version=1)` 注册一个明确选取公共数据字段的读取器；不要直接打包全部KV或整个目录。接收端忽略不认识的模块，读取已支持模块版本；只在破坏性合同变更时提升主版本。更新源码后重新启动工作台加载新采集器即可。

运行 `python -m pytest tests/test_data_sync.py -q` 可验证字段白名单、事件分页与游标、失败队列、原子改名、丢失回执后的重复上传处理，以及本机临时SFTP服务器的密钥认证和错误主机公钥拒绝。测试不连接生产接收服务器，也不读取真实密钥。

传输实现参考：[Paramiko SSHClient](https://docs.paramiko.org/en/stable/api/client.html)、[SFTP](https://docs.paramiko.org/en/stable/api/sftp.html)。
